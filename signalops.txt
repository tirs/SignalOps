1) PRODUCT OVERVIEW
====================================================================

App Name: SignalOps (Working Title)
Type: Multi-tenant analytics + operations dashboard
Use Case: Track KPIs, incidents, tasks, and data quality in one place.
Audience: Ops/Analytics leads + managers.

Core Concept:
- Ingest a dataset (CSV upload + scheduled import)
- Validate and persist to Postgres
- Provide KPI dashboards + drill-down

====================================================================
2) FEATURES (WHAT WILL “SHOCK” HIM)
====================================================================

2.1 Authentication + Roles (Non-Negotiable)
- Email/password login (hashed) with session management
- Roles: Admin, Analyst, Viewer
- Permissions enforced server-side (not just UI hiding)
- Password reset flow (token-based)

2.2 Multi-Page App (Real Navigation, Real State)
- Overview (KPI + trend)
- Drill-down Explorer (filters, joins, search, paging)
- Data Quality (validation results, failed rows, rules)
- Anomalies (detected events, severity, timeline)
- Incidents / Actions (create, assign, status, comments)
- Reports (PDF/HTML export + scheduled snapshot)
- Admin (users, roles, tenants, settings, job runs)

2.3 Data Layer That Looks Like Production
- Postgres backing store with migrations
- Schema design that is explicit and documented
- Data import pipeline:
  - Upload CSV -> staging -> validate -> commit
  - Store validation errors per row + per rule
  - Keep versioned imports (import_id)
- Job run logging (start/end, status, error trace)

2.4 Data Quality Rules Engine
- Configurable validation rules:
  - Required columns
  - Type checks
  - Range checks
  - Allowed values
  - Uniqueness constraints
- Results stored and visualized:
  - Error count by rule, by column
  - “Top failing rows” table
  - Download error report CSV

2.5 Anomaly Detection That Is Simple but Legit
- Baseline model per metric:
  - rolling mean/std OR robust median/MAD
- Detect outliers:
  - severity levels (low/medium/high)
- Explanations:
  - show baseline, thresholds, and current value
- Store anomalies to DB and display:
  - timeline chart
  - anomaly table with drilldown

2.6 Workflow (This makes it feel real)
- Convert anomaly -> incident
- Assign owner
- Status transitions (Open, Investigating, Mitigated, Closed)
- Comments thread per incident
- SLA timer and “age” view
- Audit trail of all changes

2.7 Performance (No “Shiny is slow” excuses)
- Server-side DataTables / paging for large tables
- Caching:
  - memoise or local cache keyed by filters
- Async:
  - background job for imports and heavier computations
- Guardrails:
  - limit row preview, chunked processing for uploads

2.8 Export / Reporting
- Generate PDF/HTML report (parameterized)
- Export filtered data as CSV
- Export anomaly log + incidents log

2.9 Observability (This is rare in freelancers)
- Structured logging (json-style)
- Health endpoint / status panel
- Metrics:
  - active sessions
  - query timings
  - import durations
- Error capture:
  - global error handler with friendly UI + server logs
- Admin view: job history + failures

5) DEPLOYMENT ON HOSTINGER (REALISTIC PLAN)
====================================================================

Assumption:
You have Hostinger VPS access (Ubuntu). If only shared hosting exists,
you still can deploy via container if VPS supports it; otherwise you need
a VPS. (Production-grade requires VPS.)

Steps:
- Provision VPS (Ubuntu)
- Install Docker + docker compose
- Setup Nginx reverse proxy + SSL
- Configure environment variables (DB creds, secrets)
- Run migrations
- Bring up stack:
  - postgres container (or external DB)
  - shiny container
  - nginx container
- Add backups:
  - daily pg_dump -> /backups
  - rotate backups (7/30 days)
- Add monitoring:
  - health endpoint
  - uptime checker (optional)
